# Auralis Private Preview

The private preview gives a small number of volunteers early access to a
potential next Auralis release. Its purpose is to test whether the product is
useful in real editor workflows before any public launch or paid offering.

## What This Preview Is

- A no-cost, opt-in test lasting about 7–14 days.
- A chance to influence usability, compatibility, documentation, and release
  priorities.
- Pre-release software that may contain defects or change before release.

It is not a purchase, a promise that every preview feature will ship, or a
request for a positive review. Preview access is not compensation, and no
incentive depends on what a tester says.

## Who Should Volunteer

You do not need to be a professional software developer. A useful tester is
someone who:

- Uses a supported editor for ordinary coding, configuration, documentation,
  or infrastructure work.
- Can use the preview in a normal workflow for several days.
- Will report both what works and what does not.
- Can avoid sharing confidential project material in screenshots or reports.

## How It Works

1. Submit the public
   [volunteer form](https://github.com/bertrandmbanwi/auralis-support/issues/new?template=private_preview.yml).
2. A small first group will be selected based on editor and workflow coverage,
   not praise or willingness to post a review.
3. Selected volunteers are notified on their application issue and receive a
   private GitHub invitation with installation and download instructions.
4. Use the preview in a normal workflow for 7–14 days when possible.
5. Submit the public
   [preview feedback form](https://github.com/bertrandmbanwi/auralis-support/issues/new?template=preview_feedback.yml),
   or use the private contact path supplied with the build for anything that
   would expose unreleased information.

Applying does not guarantee selection. Keeping the initial group small makes
it possible to respond to every tester and fix problems before expanding the
preview.

## Protect Private Information

GitHub issues in this repository are public. Never post:

- Email addresses or other contact information.
- Private source code, filenames, repository names, paths, or environment
  details.
- Secrets, credentials, license keys, or diagnostic data you have not reviewed.
- Preview builds, download links, screenshots, or unreleased product or brand
  names.

Use a small public example when reporting a problem. For sensitive or
unreleased details, use only the private contact path provided with the build.

## What We Measure

The preview does not add telemetry. Feedback is user-initiated. We are looking
for evidence such as:

- Whether the preview installed and remained installed.
- Whether it was used repeatedly rather than only opened once.
- Which parts delivered real value.
- Which defects, confusing steps, or missing features blocked use.
- Whether the tester would choose it over their current setup.
- What the tester would realistically do if a future release were paid.

An honest “I would not pay for this” is as useful as positive feedback.
Repeated use and retention are stronger evidence than a hypothetical answer
about future payment, so the two are evaluated separately.
